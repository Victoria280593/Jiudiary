# JiuDiary

Короткая шпаргалка для работы с репозиторием через SourceTree.

## Что где находится

- `front` - фронтенд на Next.js.
- `back` - API на ASP.NET Core.

Локально:

- фронт: `http://localhost:3000`
- API: `http://localhost:5136`

На сервере:

- master frontend: `http://217.114.15.222:3001`
- API: `http://217.114.15.222:5136`
- frontend ветки `Dima-test`: `http://217.114.15.222:3002`

Важно:

- push в `Dima-test` запускает автодеплой фронта на `3002`
- API сейчас общий и живет отдельно на `5136`
- если меняешь только фронт, работаешь в папке `front`
- если меняешь API, работаешь в папке `back`

## Главные правила

- Диме работать только в ветке `Dima-test`, если отдельно не сказали иное.
- В `master` напрямую не коммитить.
- Перед началом работы всегда сначала забрать свежие изменения.
- Перед push проверить, что коммитишь только свои файлы.
- В репозиторий нельзя пушить пароли, ключи, токены и `.env` с секретами.

## Что означают кнопки в SourceTree

- `Получить` / `Fetch` - просто проверяет, что появилось нового на GitHub. Локальные файлы не меняет.
- `Извлечь` / `Pull` - забирает изменения из удаленной ветки к себе в текущую ветку.
- `Зафиксировать` / `Commit` - создает локальный коммит на твоем компьютере.
- `Отправить` / `Push` - отправляет локальные коммиты на GitHub.
- `Слить` / `Merge` - вливает одну ветку в другую.
- `Переключить` / `Checkout` - перейти на нужную ветку.

## Как Диме работать каждый день

1. Открыть репозиторий в SourceTree.
2. Нажать `Получить` (`Fetch`).
3. В списке веток слева дважды нажать `Dima-test`, чтобы перейти в нее.
4. Нажать `Извлечь` (`Pull`), чтобы подтянуть свежую `Dima-test`.
5. Внести изменения в код.
6. Во вкладке `File Status` проверить список файлов.
7. Отметить галочками только нужные файлы.
8. Нажать `Зафиксировать` (`Commit`).
9. Написать понятное сообщение коммита. Например: `fix calendar layout on mobile`.
10. Нажать `Отправить` (`Push`) и отправить изменения в `origin/Dima-test`.
11. После push фронт ветки `Dima-test` должен обновиться на `http://217.114.15.222:3002`.

## Как понять, что все сделал правильно

- Текущая ветка сверху должна быть `Dima-test`.
- В окне push целевая ветка должна быть `origin/Dima-test`.
- В коммит не должны попасть чужие или случайные файлы.
- Если меняли фронт, проверять результат надо на `3002`.
- Если меняли API, одного push в `Dima-test` для отдельного фронтового приложения недостаточно, потому что API общий.

## Как влить `master` в `Dima-test`

Это нужно, когда в `master` появились полезные изменения, и их надо забрать в рабочую ветку Димы.

1. Нажать `Получить` (`Fetch`).
2. Переключиться на `Dima-test`.
3. Нажать `Извлечь` (`Pull`) для `Dima-test`.
4. Найти ветку `master`.
5. Нажать по `master` правой кнопкой.
6. Выбрать `Слить master в текущую ветку`.
7. Если конфликтов нет, SourceTree завершит merge сам.
8. Если есть конфликты, их нужно решить, затем сделать commit merge.
9. После этого нажать `Отправить` (`Push`) в `origin/Dima-test`.

## Как влить `Dima-test` в `master`

Это делать только когда изменения проверены и готовы к основной версии.

1. Нажать `Получить` (`Fetch`).
2. Переключиться на `master`.
3. Нажать `Извлечь` (`Pull`) для `master`.
4. Нажать правой кнопкой по ветке `Dima-test`.
5. Выбрать `Слить Dima-test в текущую ветку`.
6. Проверить, что все собрано и работает.
7. Сделать merge commit, если SourceTree попросит.
8. Нажать `Отправить` (`Push`) в `origin/master`.

После push в `master`:

- фронт master работает на `http://217.114.15.222:3001`
- API остается на `http://217.114.15.222:5136`

## Как писать коммиты

Коммит должен коротко объяснять, что изменено.

Нормальные примеры:

- `fix mobile calendar layout`
- `add student trainer requests`
- `update login role switcher`

Плохие примеры:

- `123`
- `fix`
- `changes`
- `test`

## Если что-то пошло не так

- Не паникуй и не жми подряд все кнопки.
- Сначала посмотри, в какой ты ветке.
- Потом посмотри, есть ли незакоммиченные файлы.
- Если SourceTree показывает конфликт, не push, пока конфликт не решен.
- Если не уверен, лучше ничего не вливать в `master`.

## Самая короткая схема

Для обычной работы Димы:

`Fetch -> Checkout Dima-test -> Pull -> изменить код -> Commit -> Push`

Для обновления ветки Димы изменениями из `master`:

`Fetch -> Checkout Dima-test -> Pull -> Merge master into Dima-test -> Push`

Для отправки проверенных изменений в основную версию:

`Fetch -> Checkout master -> Pull -> Merge Dima-test into master -> Push`
